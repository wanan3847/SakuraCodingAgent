一个理解工程的编码 Agent

先理解代码。
再交付改动。

Sakura 把仓库分析、任务规划、Agent 协作和真实验证连成一条可审阅的工作流。

开始使用 ↗ 阅读快速指南 ›

代码任务，
不止是写入文件。

从目标到变更，每一步都有来源、有状态，也有可以检查的结果。

  1. 理解

    从仓库中找到相关文件、符号与测试。

  2. 规划

    按依赖拆分任务，确定角色和修改范围。

  3. 执行

    在独立工作区完成修改，保留完整变更。

  4. 验证

    运行项目检查，汇总报告与 diff 供你审阅。

为真实工程任务设计。

五个模块共用一套任务记录。你可以追踪决策、修改和验证证据。

01

动态任务规划

将复杂目标拆成带依赖关系的任务。执行遇到新信息时，可以基于证据调整计划。

src/planning/
02

多 Agent 协作

按角色和写入范围调度子 Agent。依赖任务会接收前序产物，独立任务可以并行。

src/orchestrator/
03

仓库理解

解析 TypeScript 与 JavaScript 的符号、引用和测试关系，为上下文选择提供依据。

src/repo-intelligence/
04

隔离工作区

用 Git worktree 保存独立改动，检查权限与冲突，再以可重放产物交付。

src/workspace/
05

经验与技能

记录有来源的运行经验。候选技能经过真实回放和效果门槛，再进入发布流程。

src/experience/

熟悉 Pi。
保持自己的配置。

Sakura 复用 Pi 的模型会话、工具、主题与扩展接口。独立启动时使用自己的设置目录，不读取个人或项目的 Pi 配置。

了解 Pi 生态兼容 ›

安装后的独立命令

sakura init YOUR_MODEL
sakura
配置目录：~/.sakura/agent

把能力边界说清楚。

当前版本面向 TypeScript 与 JavaScript 工程。Sakura 已完成多轮固定任务验收，评测也保留了未通过的结果。

目前可用

计划、协作、隔离执行、验证、取消恢复、运行历史、diff 审阅与 Pi 资源管理。

仍在拓展

其他语言会退回通用文件工具；经验模式聚类尚未实现。现有固定任务评测没有证明多 Agent 普遍优于单 Agent。

从你的下一个任务开始。

准备一个本地 Ollama 模型，在终端中启动 Sakura。

查看完整安装说明 ›
npm 全局安装
git clone <repo> && cd SakuraCodingAgent
npm ci --ignore-scripts
npm i -g .
sakura init YOUR_MODEL
sakura

在仓库根目录执行（仓库根就是包根目录）。也可以 npm run pack 后用 npm i -g ./sakura.tgz 分发 tarball，或 npm run app 一次完成打包与安装。需要 Node.js 22.19 或更新版本；YOUR_MODEL 是已安装的 Ollama 模型名。
