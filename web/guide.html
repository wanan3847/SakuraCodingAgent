开始使用 ↗

开始使用 Sakura。

准备运行环境与本地模型，在一个独立配置里完成第一次计划、执行和交付。

环境安装工作流Pi 生态能力边界

运行环境

需要 Node.js 22.19 或更新版本。默认使用本地 Ollama 模型，请先启动 Ollama 并下载所需模型。

命令中的 YOUR_MODEL 是占位名称，替换为本地已安装的模型名称。初始化不会下载模型；首次联网初始化会准备缺失的 fd 与 rg 搜索工具。

安装与启动

仓库根目录就是包根目录，用 npm 安装（推荐）：

git clone <repo> && cd SakuraCodingAgent
npm ci --ignore-scripts
npm i -g .
sakura init YOUR_MODEL
sakura

分发到别的机器时用打包产物；npm run app 一步完成打包与全局安装：

npm run pack
npm i -g ./sakura.tgz
sakura doctor

为什么不用 curl | sh：curl 安装需要额外托管安装脚本与 tarball、自己维护校验和回滚；npm 已经提供版本锁定、完整性校验和一条命令卸载（npm rm -g sakura-coding-agent）。运行依赖随包安装，不需要全局 Pi。

安装一次后，在任意项目目录运行 sakura。全局安装需要 npm 全局目录可写。若已准备好 fd 和 rg，离线初始化可加 --offline。云端模型用 sakura --cloud，然后在终端里用 Pi 原生 /login 与 /model。账号数据、会话与运行记录都在 ~/.sakura，不导入个人 Pi 配置。

源码开发（不安装）：

npm ci --ignore-scripts
npm run check
npm run init -- YOUR_MODEL
npm start
npm run web

计划与交付

在独立终端使用短命令：

/plan 修复登录刷新问题，保持公开接口不变
/subagent 修复登录刷新问题，保持公开接口不变
/history
/status

计划会保存为任务图。执行按依赖调度 Agent，收集变更与验证结果；产物由你审阅后再应用。产物保存本身不会修改目标分支。

  • /cancel 或 Ctrl+Shift+X 取消工程运行。
  • /sakura-resume 恢复已保存的工程运行；--continue 续接最近的终端会话。
  • /instruct 在运行中补充指令。

Git worktree 提供工作区隔离，操作系统沙箱提供另一层命令执行限制。若系统不允许所需隔离，受保护执行会拒绝运行。

Pi 生态与独立配置

独立配置默认位于 ~/.sakura/agent，不会导入个人 ~/.pi 或目标项目的 Pi 设置。模型、凭证、会话、扩展、技能、提示词与主题都保存在 Sakura 自己的目录中。

sakura install npm:PACKAGE@VERSION
sakura packages
sakura remove npm:PACKAGE@VERSION

资源通过 Pi 原生包管理和加载接口接入。扩展属于可执行代码；每个第三方包的版本、权限和网络行为仍需单独检查。当前 Sakura 固定使用 Pi 1.1.0 API。

当前能力边界与后续方向

Sakura 本轮核心任务清单已完成，并通过固定任务与安装验收。下列边界仍需要持续投入，避免把小样本验收解释成普遍能力：

  • 更广的语言理解。 仓库图分析集中在 TypeScript 与 JavaScript。其他语言可以继续通过文件搜索和读取使用，但没有同等的符号级索引和测试映射。
  • 跨任务经验聚类。 当前已有经验去重、检索和带审批的技能候选流程；重复模式聚类尚未实现。
  • 多 Agent 的适用性判断。 固定任务矩阵中，Sakura 完整流程为 20/30，no-multi 与 fixed-plan 各为 25/30。现有结果没有证明多 Agent 普遍更好，后续需要按任务类型决定何时并行，以及覆盖更多模型、仓库和硬件。
  • 更广的冲突与故障验证。 已有 Git worktree、产物集成、冲突报告、取消和恢复；语义级冲突合并、长期运行故障注入还需要拓展。
  • 沙箱兼容范围。 Linux bubblewrap/seccomp 路径已在固定环境验收。旧版过滤会拒绝 clone3，少数依赖该调用的 Node 检查可能失败关闭；不同主机仍需分别验证。

完整审计、任务证据和评测局限见仓库的 docs/完成度审计.md、docs/任务清单.md 与 docs/实施记录.md。

项目网站与运行记录

项目介绍网站是静态页面。使用 sakura web 在本地预览；运行记录查看工具位于本地服务的 /workbench，静态网站导出不包含运行 API。

sakura web
npm run site:build

site:build 将网站导出到 .sakura/site-dist，可部署到静态网站托管服务。
