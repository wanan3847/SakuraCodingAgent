# Sakura 完成度与 Pi 插件复用审计

审计日期：2026-10-13。范围：[架构与开发路线](架构与开发路线.md)、[Pi 复用指南](Pi复用指南.md)、`docs/开发计划.md`、`docs/任务清单.md`、`docs/实施记录.md` 与当前仓库证据。已按用户授权在目标 Linux 主机的独立 root 测试目录完成 Linux 验收；没有修改系统包、`/etc`、AppArmor、冻结评测目录或 root 的 Pi 配置。

补充：随后完成 Codex / Pi 调研后的编码能力清单，本地全量 160/160；主 Shell、项目说明、取消/预算、代码撤销、独立 MCP、Python AST 和经验模式分组已交付；模型切换已收敛为 Pi 原生 `/model`，自建切换入口与 `setDefaultModel` 调用已移除；TUI 品牌页眉只留一行标题，底栏改为 Pi 原生 footer（供应商 · 模型 · 思考级别）。见[本轮实施与验收](CODING_CAPABILITIES.md)。本轮新能力未重跑 Linux、未更新服务器，下面 Linux 数据为历史副本证据。

## 结论

**本轮定义的 S0–S5 交付清单已经完成并有证据；两份早期路线文档里的所有愿景并没有全部完成。** 旧路线将 Pi adapter、广泛语言支持、模式聚类、OS 沙箱、多 Agent 增益和演示材料都写成计划任务；其中一部分后来被官方 Pi SDK 复用原则取代，一部分只在 TypeScript 仓库/本地 macOS 环境验收，另有一部分没有证据支持“普遍有效”。因此不能用任务清单的勾选数声称原始架构愿景全部完成。

当前可确认的交付包括：Pi 1.1.0 官方 SDK/扩展接入；任务 DAG、执行调度、恢复与受控子 Agent；TS 仓库索引和 Context Pack；worktree 产物与集成；运行经验及候选技能安全生命周期；240 项固定环境矩阵；个人版安装验收；独立 Sakura TUI 和项目介绍网站。最新功能名为 `/subagent`，旧 `/run` 和 `/sakura-run` 保留为兼容别名。

- 首次受限 Linux 尝试确因旧 bubblewrap 不支持 `--disable-userns` 而失败；兼容性修正由项目 seccomp 过滤器拒绝 `clone3`、`unshare` 和 `setns`。清理 macOS AppleDouble sidecar 并隔离 `HOME` 后，完整 Linux 回归和插件体检通过，详见 `docs/实施记录.md`。AppArmor 在该主机不可用也未安装；这次验收只证明该 bwrap/seccomp 路径可执行，不宣称 AppArmor 已配置。对其他项目命令仍需单独检查旧版 seccomp 与其子进程调用的兼容性。
- Repo Intelligence 的引用/调用图覆盖集中在 TS/JS；新增 Python AST 定义及相对导入已经验收。其他语言及依赖运行时行为的动态调用图没有被验收。
- 经验 fingerprint 去重、检索与确定性问题模式分组已实现；没有语义聚类、通用效果改善或自动通过效果门槛的证据。

## Pi 官方生态插件筛选

以下版本与说明取自 Pi 官方包目录/每个包列出的上游 README，核对日为 2026-10-13。这里只做插件评估，没有安装第三方插件到 Pi profile；Linux 验收使用独立测试副本，不更改原有服务器部署。

| 插件 | 建议 | 与 Sakura 的关系 |
| --- | --- | --- |
| [`pi-web-access`](https://pi.dev/packages/pi-web-access) | 值得作为**可选 package**试用 | 搜索、抓取网页、GitHub 仓库克隆、PDF/视频功能省去自行维护 provider 集成。官方目录当前列 0.39.0/MIT。默认可尝试多个远端 provider；应显式设置 routing 和凭据策略，并先在 Sakura 独立 profile 做工具/网络审查。若保持当前 `localOnly`，需确保它不悄悄引入外网调用。 |
| [`@langchain/langsmith-pi-extension`](https://pi.dev/packages/@langchain/langsmith-pi-extension) | 适合**可选观测集成**，暂不作为默认依赖 | 0.2.1/MIT，可跟踪 turns、tool calls、tokens 和模型调用；默认关闭。会读取 `~/.pi/langsmith.json` 与 `<cwd>/.pi/langsmith.json`，与 Sakura 隔离配置冲突；应使用显式 `extensionFactories` 配置和 Sakura 自己的 opt-in 密钥/项目。子 Agent 目前不自动加载扩展，追踪要补 parent-child run 关联。 |
| [`pi-subagents`](https://pi.dev/packages/pi-subagents) | 借鉴体验与编排；不要替换 Sakura DAG | 0.78.0/MIT，提供自然语言委派、后台任务、舰队视图、工作流与多个 spawn 限额。它的执行/生命周期与 Sakura 的任务图、worktree、产物集成、恢复不同；全量共存会重复入口和多智能体层。目前 Sakura 已有 `/subagent`，并非名字一样就可用其 runtime；后续可单独验证选择性互操作。 |
| [`@plannotator/pi-extension`](https://pi.dev/packages/%40plannotator/pi-extension) | 若要计划可视化审阅，建议做**独立可选插件试点** | 0.28.17，MIT/Apache-2.0；可为计划逐条批注和批准。它的 Markdown plan mode 不直接等于 Sakura 已保存的 DAG/planId/version，也不能替代已建立的技能发布审批门禁，需要适配层才能保持同一份计划。 |
| [`pi-lens`](https://pi.dev/packages/pi-lens) | 有较强代码反馈能力，暂缓直接叠加 | 4.4.3/MIT；提供 LSP、lint/type/format、AST、诊断和语言服务，但范围与 Sakura Repo Intelligence/Verification 部分重叠，带多个 peers 与外部工具。应该按语言/体积先做隔离评估，防止与当前工作区写权限、检查证据及自动修复发生冲突。 |

当前应直接复用的是 Pi 1.1.0 的 SDK、resource/package loader、Extension/Skill/MCP 和 session 工具接口；Pi 网站说明当前 Pi 已内置 MCP 与 Codemode。因此 `pi-mcp-adapter` 不构成 Sakura 核心缺口。第三方插件可通过 Sakura 本地 profile 的包管理器隔离安装和卸载，但任何插件都是可执行代码；逐个审核来源、license、依赖、网络、文件权限、命令冲突、子 Agent 暴露范围后再选择安装。[Pi 官方 Packages](https://pi.dev/packages) · [Pi 官方介绍](https://pi.dev/)

### 插件验证的最小下一步

如果要实际试一个，优先用独立 Sakura profile 开启 `pi-web-access` 的明确搜索 provider，验证 `/packages` 安装/移除、网络与 local-only 策略；若目标是 LangSmith，则先做 `extensionFactories` 适配并确认不会读取个人 `~/.pi` 或项目 `.pi` 配置。不要把插件直接复制进 Sakura 源码；保持可通过 Pi package manager 单独更新和回滚。
