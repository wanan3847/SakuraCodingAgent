# 🌸 Sakura 樱花风格规范

版本：0.4 · 日期：2026-10-13。Night/Light 和真实阶段 widget 已实现；原生加载、40/80/120 列、无色/无 emoji、全部业务阶段与 JSON 数字一致性已检查。真彩与 256 色各 39 组前景/背景检查覆盖代码、Markdown、工具面板、错误、diff、选中与搜索区域；实际终端颜色依其配色设置而异。

## 1. 风格方向

关键词：樱花、安静、清晰、轻盈。用粉色表达品牌，用明确的状态和证据表达工作进度。

品牌名统一为 **Sakura Coding Agent**，短名称 **Sakura**，命令名 `sakura`。标题使用一次 `🌸`；正文、日志和每条工具调用保持简洁。程序字段、文件名和机器输出使用稳定英文标识。

第一版沿用 Pi 终端界面，保留完整的代码阅读空间。默认 Sakura Night，提供 Sakura Light；支持关闭颜色和 emoji。Pi 原有的目录、模型、usage、会话与输入交互直接复用，新增展示集中在品牌与任务阶段。

## 2. 色彩

以下是设计参考色；实现以 `themes/` 中的颜色角色为准。脚本使用 Pi 公开 Theme 输出及标准 xterm 256 色调色板测量，正文、错误、代码和 diff 对比度目标为 4.5:1，次级信息目标为 3:1。四组测量均达标，正文最低为 Light 256 色的 4.54:1；报告位于 `.sakura/release/themes/contrast.json`。终端背景应与所选 Night/Light 背景相配。

Light 的自定义消息标签在粉色面板上使用更深的 `#7A2450`，保证 256 色下的文字对比度；其他品牌角色继续采用樱花主色。

| 角色 | Sakura Night | Sakura Light | 用途 |
| --- | --- | --- | --- |
| 背景 | `#18141C` | `#FFF8FB` | 主背景参考 |
| 面板 | `#241E2A` | `#F6EAF0` | 用户消息、任务摘要 |
| 正文 | `#F3EDF4` | `#302631` | 回答和工具输出 |
| 次级文字 | `#B6A8BB` | `#716273` | 路径、时间、辅助信息 |
| 樱花主色 | `#F4A8C7` | `#A63668` | 品牌、标题、当前阶段 |
| 辅助色 | `#C2B1F0` | `#6C4FA0` | 链接和选中项 |
| 成功 | `#98D6B0` | `#25683E` | 检查通过、完成 |
| 警告 | `#EAC581` | `#855915` | 降级、未验证、待处理 |
| 错误 | `#F38F9A` | `#AF2946` | 检查失败、连接错误 |
| 边框 | `#74617F` | `#A08BA2` | 分隔、焦点区域 |

粉色集中在品牌和焦点。diff 的新增与删除继续使用绿色与红色，并保留 `+`、`-`。错误、警告和成功必须同时带文字标签，不能只靠颜色区分。

Pi 主题需要覆盖完整的颜色角色，包含代码、Markdown、工具和 diff；从所选版本的内置主题复制后修改，按该版本 schema 校验。[官方主题说明](https://pi.dev/docs/latest/themes)

## 3. 终端布局

下面展示目标状态，内容和数据为示意。

```text
🌸 Sakura Coding Agent
~/projects/demo  ·  本地模型  ·  Sakura Night

任务：修复登录 token 刷新

计划                            2/4
  [✓] 定位相关代码
  [✓] 实现修复
  [>] 运行项目检查
  [ ] 整理交付

检查：npm test
...工具输出与代码 diff...

验证中 · 运行 00:42 · token 3,200
> 输入任务或补充说明
```

布局优先级：任务与回答 → 代码及工具输出 → 当前阶段 → 模型/目录等辅助信息。窄终端先隐藏辅助字段，长路径按终端列宽截断；任务名和错误原因允许换行。

计划由任务数据生成，进度来自已完成节点和有效节点总数。工具运行期间显示真实活动状态；没有可靠分母时显示阶段名称。

### 状态表达

| 状态 | 显示文字 | 示例 |
| --- | --- | --- |
| 空闲 | 就绪 | “输入一个任务开始。” |
| 规划 | 规划中 | “正在定位相关文件并拆解任务。” |
| 执行 | 编码中 | “正在实现 2/4。” |
| 验证 | 验证中 | “正在运行 npm test。” |
| 等待应用 | 待应用 | “检查通过，改动已保存。” |
| 未验证 | 未验证 | “没有发现可运行的项目检查。” |
| 失败 | 失败 | “类型检查失败，报告已保存。” |
| 取消 | 已取消 | “任务已停止，改动已保留。” |
| 已应用 | 已应用 | “改动已应用，复验通过。” |

## 4. 交互与文案

文案使用简短中文，工具名、参数、路径和命令保持原样。先报告结果，再给证据和下一步。

- 启动：“🌸 Sakura 已就绪。”
- 模型失败：“无法连接本地模型，请检查 Pi 的模型与端点配置。”
- 规划降级：“模型规划失败，已使用基础计划。原因：……”
- 完成：“检查通过，改动已保存。修改 3 个文件，新增 1 个文件。”
- 失败：“测试失败。失败命令：npm test。产物与报告：……”
- 取消：“已取消。未完成节点已停止，当前改动保存在……”

已有命令如 `/sakura-plan`、`/sakura-run`、`/sakura-status` 保留清晰命名；模型、鉴权、主题和会话管理使用 Pi 原生命令。新增取消、恢复、diff 和应用入口时，先区分 Pi Session 控制与 Sakura 整轮工程任务需求，按实际缺口注册命令。

结果页按顺序展示：执行状态 → 检查状态 → 应用状态 → 文件摘要 → 证据/产物路径 → 可执行下一步。用于拷贝的命令始终放独立代码块。

## 5. 可读性与实现要求

- 中文字符、emoji 与 ANSI 的宽度通过 Pi TUI 提供的能力计算，避免直接用字符串长度布局。
- 40 列显示精简状态，80 列完整显示主要信息，120 列允许更多路径和使用量信息。
- 不支持 emoji 时将 `🌸` 替换为 `Sakura`；状态符号提供 `[done]`、`[run]`、`[fail]` 等文本降级。
- 尊重 `NO_COLOR`；print/JSON/RPC 模式按各自能力输出，不插入 TUI 装饰。
- 进度更新跟随事件，合并高频更新；流式内容沿用 Pi 渲染能力。
- UI 代码消费业务状态，主题代码负责色彩，避免界面再计算一套任务状态或 token。
- 主题资源加入 Pi manifest 和发布 files；自定义主题、header/footer 的 API 在实现前核对锁定版本。优先在已有入口接入必要 UI 钩子，独立加载/开关确有需要时再拆扩展。
