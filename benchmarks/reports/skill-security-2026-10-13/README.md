# 技能发布安全回归验收

2026-10-13。本轮 `npm run check` 完整类型检查与 144 项测试通过，零失败、零取消、零跳过。原始输出见 [check.log](check.log)，源码和日志哈希见 [verification.json](verification.json)，安全回归源码副本见 [security-regression.test.ts](security-regression.test.ts)。

| 审查要求 | 验证结果 |
| --- | --- |
| 不同候选同名不能覆盖 | 名字预留拒绝，外来正式工件保持原字节 |
| 旧版加载但包含新版正文 | 旧版完整正文包含新版，精确哈希/路径验证仍拒绝 |
| 审核后修改 description | 即使重算项目哈希和审核字段，外部权威记录不匹配仍拒绝 |
| 两进程同时修订 | 两个真实 Node 进程得到版本 2/3，文件各自保留 |
| 发布中途文件写入失败 | SKILL.md 写入后注入故障，下一操作恢复 journal/active/版本镜像 |
| 回滚 active 与文件一致 | 生效版本回到 1，path/hash 完整，latest 保持版本 2 |
| 伪造 reviewed 状态 | 完整伪造项目审批记录不能发布，权限请求也不能允许写权威目录 |

额外检查：受保护验证命令不能写外部审批目录和宿主控制代码；原地执行在 Agent 调用前拒绝；正式技能被实际加载，文件篡改时停止；自动批准拒绝不足样本及重复运行 ID，通过同设置可信回执才进入发布。

测试使用真实 Pi Session 和脚本 provider。效果门槛测试中的 token 优势是确定性测试输入，不能作为真实模型收益。用户已明确授权自动批准；真实 18 次候选对照排在现有矩阵之后，未完成前不发布效果结论。历史候选不补造权威认证。

发布的权限边界、自动批准条件、事务和平台限制见 [SKILL_SECURITY.md](../../../docs/SKILL_SECURITY.md)。本机为 macOS；远端 CI 未实际运行。这些检查不证明对 root、任意未隔离的同 UID 程序或恶意同进程扩展安全。
